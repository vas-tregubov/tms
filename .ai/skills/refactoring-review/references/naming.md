# Naming

Inspect data, temp, result, arr, val, obj, foo, and similarly uninformative names only where context is actually ambiguous. Short obvious scopes or conventional callback names can be fine.

Cite declaration/use and ambiguity; suggest one or two concrete context-supported alternatives following project/domain naming conventions. Ask a focused question when meaning is unknown rather than inventing a name. Check public API, serialization, and consumer effects before calling a rename behavior-preserving.
