# Hot Paths

Establish a genuinely hot function using profiles, frequent events/renders, call frequency, or a concrete workload argument. Separate estimates from measurements and state profiling needs.

Check unnecessary allocations, repeated calculations, avoidable traversals, and algorithmic improvements. Distinguish micro-optimization from order-of-magnitude improvement; quantify only supported gains. Suggest React memoization only when costs/dependencies justify it.

Give operation/location, workload, before/after costs, and minimal alternative. Warn if readability or memory worsens or caching adds invalidation/lifecycle complexity. Do not prescribe workers, caches, or dependencies speculatively.
